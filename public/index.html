🎓 Essential Viva Voce Questions & Answers
Defense Preparation

Q1: Why is an HTTP Basic Auth token vulnerable to a replay attack?

A: Weak tokens are static strings without embedded nonces, client bindings, or freshness timestamps. An attacker intercepting the token can re-transmit it at will, and the server cannot determine whether it originated from the legitimate user or an adversary.

Q2: How does Kerberos prevent replay attacks?

A: Kerberos requires an Authenticator containing the client's current timestamp encrypted with the session key. The server enforces a clock-skew window (typically $\pm 5$ minutes) and records all recently seen timestamps in a Replay Cache. If a duplicate authenticator is re-sent, the server rejects it with KRB_AP_ERR_REPEAT.

Q3: What is the core difference between Kerberos and PKI?

A: Kerberos relies on symmetric key cryptography and requires a centralized, continuously online Key Distribution Center (KDC). PKI relies on asymmetric key pairs and digital signatures; Root CAs can remain offline because certificates are mathematically self-verifiable using the CA's public key.

Q4: What is Mutual TLS (mTLS) and how does it prevent Man-in-the-Middle?

A: In standard TLS, only the server proves its identity. In mTLS, both client and server exchange X.509 digital certificates and prove ownership of their corresponding private keys via digital signatures (CertificateVerify). An eavesdropper or MITM lacks the private keys and cannot impersonate either party.
